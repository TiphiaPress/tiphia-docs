# 架构总览

TiphiaPress 采用后端、前端、主题、插件拆分的架构。目标是让核心稳定、主题自由、插件扩展明确。

## 仓库分工

| 仓库 | 职责 |
| --- | --- |
| `tiphia` | Rust 后端核心、内置后端插件、迁移工具、Dockerfile。 |
| `tiphia-frontend` | 管理后台、博客前端骨架、默认主题、前端插件注册机制。 |
| `tiphia-docs` | GitHub Pages 文档站。 |
| 独立主题仓库 | 主题作者维护自己的主题目录。 |
| 独立插件仓库 | 插件作者维护后端 crate 和前端插件目录。 |

## 请求链路

博客前台请求链路：

```text
浏览器 -> 前端静态资源 -> API Base -> 后端 REST API -> 数据库/插件 Hook
```

后台请求链路：

```text
浏览器 -> Admin 页面 -> 带 JWT 的 API 请求 -> 后端权限检查 -> 服务层 -> 数据库
```

插件链路：

```text
后端业务事件 -> HookContext -> 插件处理 -> 可选路由/配置/邮件/外部服务
前端页面渲染 -> HookSlot -> 前端插件渲染组件或副作用
```

## 分层边界

| 层 | 应该做什么 | 不应该做什么 |
| --- | --- | --- |
| 后端路由 | 参数提取、权限检查、调用服务、返回 JSON。 | 写复杂业务逻辑。 |
| 后端服务 | 数据校验、事务、Hook 调度、核心业务。 | 依赖前端实现细节。 |
| 后端插件 | 使用 Hook 扩展业务，注册独立路由和配置。 | 修改核心业务代码。 |
| 前端骨架 | 获取数据、路由、插件注册、后台管理。 | 写死博客主题 UI。 |
| 主题 | 渲染博客页面和主题配置。 | 直接管理全局插件状态。 |
| 前端插件 | 注册 Hook 内容、配置面板、额外页面。 | 要求主题必须改代码才能使用。 |

## 数据流原则

前台博客页面遵循：

```text
骨架获取数据 -> 主题接收 props -> 主题渲染 -> 插件通过 Hook 补充内容
```

这样主题可以完全替换，插件也可以在不同主题中复用。

## 扩展原则

当一个新能力需要扩展核心流程时，优先顺序是：

1. 检查已有 Hook 能否覆盖。
2. 如果不能，给核心补通用 Hook。
3. 插件使用 Hook 实现功能。
4. 文档记录 Hook 输入、输出和注意事项。

不要为了某个插件在核心业务里写插件名判断。
