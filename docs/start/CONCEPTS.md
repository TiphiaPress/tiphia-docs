# 核心概念

这页解释 TiphiaPress 中最常见的概念。读完后再看 API、插件或主题文档会顺很多。

## 后端核心

后端仓库负责数据、认证、权限、插件后端、迁移、日志、限流和 REST API。它不负责渲染博客页面，也不内置后台静态资源。

推荐理解为：后端只回答“数据是什么”和“动作是否允许”。

## 前端骨架

前端骨架负责：

- 拉取后端数据。
- 管理路由。
- 管理后台页面。
- 管理前端插件注册。
- 把博客数据交给当前主题渲染。

博客页面的视觉结构不应写死在骨架里。骨架只提供数据容器和主题接口。

## 主题

主题负责博客前台展示，包括首页、文章页、页面、时间线、分类标签归档、评论区、外链提示、页脚和主题配置面板。

主题可以决定是否放置前端 Hook 插槽。默认主题会尽量放全，让插件有足够插入点。

## 插件

插件可以有两部分：

- 后端插件：Rust crate，跟主框架一起编译，注册 Hook、路由、配置 schema、迁移等。
- 前端插件：React 模块，注册后台配置面板、前台组件、额外路由、Hook 渲染内容。

插件不应要求用户修改主业务代码。需要扩展业务流程时，应先补 Hook，再让插件使用 Hook。

## Options 表

`options` 表是核心键值存储。它用于站点设置、插件状态、插件配置、主题配置、浏览量、一次性 token 等。

开发约定：

| Key | 用途 |
| --- | --- |
| `site:settings` | 站点设置。 |
| `plugin:{name}:state` | 插件启用状态。 |
| `plugin:{name}:config` | 插件配置。 |
| `theme:{name}:config` | 主题配置。 |
| `post:view:{post_id}` | 文章/页面浏览次数。 |

写入新 key 前，请在开发文档中记录契约，避免迁移工具、主题和插件踩坑。

## 路由约定

前端真实路由是：

| 类型 | 路由 |
| --- | --- |
| 文章 | `/posts/{slug}` |
| 页面 | `/pages/{slug}` |
| 自定义导航页面 | `/custom-pages/{slug}` |
| 分类 | `/categories/{id}` |
| 标签 | `/tags/{id}` |
| 时间线 | `/timeline` |
| RSS | `/feed.xml` |
| Atom | `/atom.xml` |
| Sitemap | `/sitemap.xml` |

后端生成公开链接时应尽量匹配这些前端路由，而不是使用历史的 `/archives/{slug}`。
